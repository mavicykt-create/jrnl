Внутренний сайт для бригады: объекты, задачи, исполнители, сроки, прикреплённые файлы и история — кто что менял.

Работает на чистом Node.js без единой внешней библиотеки. Данные лежат в постоянном хранилище Amvera (`/data`): `db.json` — задачи и история, `uploads/` — приложенные файлы.

## Установка: GitHub → Amvera

### 1. Положить код в GitHub
1. Создайте на github.com новый репозиторий, например `zhurnal-rabot` (можно приватный).
2. Загрузите туда содержимое этой папки — `server.js`, `package.json`, `amvera.yml`, `.gitignore`, папку `public`. Через веб-интерфейс: **Add file → Upload files**, перетащить всё, **Commit changes**.

Через терминал то же самое:
```bash
git init
git add .
git commit -m "Журнал работ"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/zhurnal-rabot.git
git push -u origin main
```

### 2. Создать приложение в Amvera
1. Зайдите на amvera.ru → **Создать проект** → тип **Приложение**.
2. Имя проекта, тариф (для такой задачи хватает самого младшего).
3. Способ доставки кода — **Через GitHub**: подключите аккаунт GitHub, выберите репозиторий и ветку `main`.
4. Конфигурация: файл `amvera.yml` уже лежит в репозитории, Amvera подхватит его сам. Если панель просит заполнить поля вручную:
   - Окружение: **Node.js**, инструмент **npm**, версия **20** (если версии 20 нет — поставьте 18, код рассчитан на обе)
   - Скрипт запуска: `server.js`
   - Порт: `80`
   - Постоянное хранилище: `/data`
5. Нажмите **Собрать**. Через минуту-две статус станет «Приложение запущено».
6. В разделе **Настройки → Домены** включите бесплатный домен вида `имя-логин.amvera.io`. Дайте эту ссылку Кате, Жене и Ариану.

### 3. Обновлять потом
Любой коммит в `main` на GitHub → в Amvera нажать **Пересобрать**. Данные при этом не теряются: они в `/data`, а не в коде.

## Полезные настройки

**Сменить пароль.** В Amvera: **Переменные окружения** → добавьте `APP_PASSWORD` со своим значением → пересоберите. Ничего править в коде не нужно.

**Изменить состав людей.** В `server.js` вверху есть список `USERS` (id, имя, цвет) — и такой же короткий список `PEOPLE` в `public/index.html` для экрана входа. Поправьте оба, закоммитьте, пересоберите.

## Как этим пользуются

- **Вкладки** сверху — объекты. Цифра в кружке — сколько задач в работе. Двойной щелчок по вкладке переименовывает объект, «+ объект» добавляет новый.
- **Строка добавления** — что сделать, кто делает, срок. Enter добавляет.
- **Срок** подсвечивается: жёлтым за три дня, красным после срока. В шапке считается «просрочено: N». Кнопка «Сначала срочные» сортирует по дате.
- **Скрепка 📎** раскрывает карточку: полная заметка и файлы. Файл перетаскивается мышью или выбирается кнопкой, до 15 МБ.
- **Подпись под задачей** — кто трогал её последним и когда. Кнопка **История** в шапке показывает всю ленту изменений: кто добавил, кто отметил сделанным, кто снял срок, кто приложил счёт.
- **Скачать копию** — выгружает задачи и историю одним файлом. Раз в месяц не лишнее.
- Страница сама подтягивает чужие правки раз в 15 секунд.

На телефоне: откройте ссылку → «Поделиться» → «На экран Домой», получится иконка как у приложения.

## О чём стоит знать

**Пароль один на троих и простой.** По подписи в истории видно, кто вошёл, но человек, знающий пароль, может войти под любым из трёх имён — это учёт, а не защита от своих. Если понадобится по-настоящему разделить доступ (у каждого свой пароль, у прораба — только свои объекты), это делается, но потребует отдельной работы.

**Ссылка без пароля не работает** — ни задачи, ни файлы посторонним не отдаются: страница файла тоже проверяет вход.

**Одновременная правка.** Каждое действие уходит на сервер отдельно, поэтому Катя и Женя могут работать параллельно. Совпасть можно только в одной ячейке в одну секунду — тогда останется тот вариант, что пришёл вторым, и оба следа видны в истории.

**Резервная копия.** Amvera держит `/data` постоянным, но копию раз в месяц кнопкой «Скачать копию» лучше делать: она защищает и от случайного удаления объекта.
